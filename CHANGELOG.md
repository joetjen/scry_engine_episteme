# Changelog

## [Unreleased]

### Added

- Initial release: `Scry.Engine.Episteme` -- a real `Scry.Core.EngineBehaviour` implementation for the `logic` kind (lang_spec.md §8.4), backed by [Episteme](https://hex.pm/packages/episteme) instead of `scry_logic`'s own hand-rolled reference `conn`. `conn` is a plain `Episteme.Database.t()`; `execute/3` resolves a call-shaped source and any `WHERE`-embedded goal calls into a combined `Episteme.Term.Compound` goal, runs it via `Episteme.query/2`, and delegates everything else (`WHERE`/`GROUP BY`/aggregates/`ORDER BY`/`LIMIT`/projection) to `Scry.Core.QueryOps.run_flat/3` unchanged -- the same shape `Scry.Logic.Executor` already established.
  Two real behavioral divergences from `scry_logic`'s own reference engine, both found running real queries rather than assumed: an undefined predicate is a `{:query_error, {:existence_error, :procedure, {name, arity}}}`, not a silent empty result (Episteme's own resolution engine raises a real ISO `existence_error`; a relation meant to be defined-but-currently-empty needs `Episteme.Database.declare_dynamic/3` called on it first, since a zero-fact relation is otherwise indistinguishable from an undefined one); and a recursive rule needs no laziness-wrapping authoring convention at all, unlike `Scry.Logic.Executor`'s own hand-written clause functions -- `Episteme.Engine` already builds each clause's goal lazily at call time.
  Predicate names are converted to atoms via `String.to_existing_atom/1`, rescued, rather than `String.to_atom/1` -- the same identifier-safety posture `scry_engine_exqlite` already takes for SQL, closing the atom-table-exhaustion vector unbounded `to_atom/1` on external query text would otherwise open. A `{:field, [name]}` goal argument is memoized into a single `Episteme.Term.Var.t()` per query (keyed by name), confirmed by property test, so two occurrences of the same query-level variable name genuinely unify rather than coincidentally matching by name alone.
